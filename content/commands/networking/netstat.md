## What is it?

`netstat` (network statistics) is a classic command-line network utility used to print detailed information about the Linux kernel's networking subsystem. It displays active TCP/UDP socket connections, listening daemon ports, kernel routing tables, masquerade connections, and multicast memberships.

## Why does it exist?

Diagnosing network health requires visibility into exactly what an operating system is communicating with. If a web server fails to start, an administrator must determine if the port is already occupied. If packets are dropping, they must inspect the routing table or check interface error counters. `netstat` exists as part of the legacy `net-tools` suite, providing a unified, multi-purpose Swiss Army knife for querying the raw network state generated by the kernel via the `/proc/net/` pseudo-filesystem.

## Syntax

```bash
netstat [address_family_options] [--tcp|-t] [--udp|-u] [--listening|-l] [--all|-a] [--numeric|-n] [--program|-p]
netstat {--route|-r} [options]
netstat {--interfaces|-i} [options]
```

## Flags

| Flag                 | Description                                                                                 | Example       |
| -------------------- | ------------------------------------------------------------------------------------------- | ------------- |
| `-a`, `--all`        | Displays all active sockets, including both listening daemons and established connections.  | `netstat -a`  |
| `-l`, `--listening`  | Restricts output strictly to sockets that are actively listening for incoming connections.  | `netstat -l`  |
| `-t`, `--tcp`        | Restricts the output specifically to TCP (Transmission Control Protocol) sockets.           | `netstat -at` |
| `-u`, `--udp`        | Restricts the output specifically to UDP (User Datagram Protocol) sockets.                  | `netstat -au` |
| `-n`, `--numeric`    | Shows raw IP addresses and port numbers, bypassing reverse-DNS and port-name resolution.    | `netstat -n`  |
| `-p`, `--program`    | Displays the PID and name of the program/application that currently owns the socket.        | `netstat -p`  |
| `-r`, `--route`      | Displays the kernel's internal IP routing table (similar to the `route` command).           | `netstat -rn` |
| `-i`, `--interfaces` | Displays a table of all network interfaces alongside statistical packet and error counters. | `netstat -i`  |
| `-c`, `--continuous` | Prints the selected information continuously, refreshing the output every second.           | `netstat -c`  |
| `-e`, `--extend`     | Displays extended networking information (such as the owning User ID and internal inodes).  | `netstat -ae` |
| `-s`, `--statistics` | Displays summary network statistics (packets received, errors) grouped by protocol.         | `netstat -s`  |

## Examples

```bash
netstat -tulpn
```

> This is arguably the most famous `netstat` combination. It lists all actively listening (`-l`) TCP (`-t`) and UDP (`-u`) ports, displaying raw numerical IPs and ports (`-n`), and attaches the associated Process ID and program name (`-p`) responsible for the binding.

```bash
netstat -an | grep TIME_WAIT
```

> This queries all connections numerically (`-an`) and pipes the output through `grep` to identify sockets stuck in the `TIME_WAIT` teardown state, heavily utilized when diagnosing high-traffic web servers suffering from port exhaustion.

```bash
netstat -rn
```

> This queries the networking subsystem for the kernel routing table (`-r`) without resolving hostnames (`-n`). It outputs destinations, gateways, subnet masks, and interface flags, validating how the OS routes outbound traffic.

```bash
netstat -ie
```

> This displays the interface statistics table (`-i`) with extended formatting (`-e`), providing a detailed view of RX/TX (Received/Transmitted) packet counts, MTU settings, and dropped or error packet anomalies for physical debugging.

```bash
netstat -s --tcp
```

> This isolates the kernel's protocol statistics (`-s`) strictly for TCP, dumping raw metric counters for metrics like active connections opened, failed connection attempts, and segments retransmitted.

## Real-World Scenarios

**Identifying Port Binding Conflicts**

```bash
sudo netstat -tulpn | grep :8080
```

> A developer attempting to launch a Node.js API receives an `EADDRINUSE` error. By executing this command with root privileges, they instantly identify the PID of the rogue Java process that previously bound to port 8080 and failed to shut down.

**Auditing Active Remote Connections**

```bash
netstat -tn | grep ESTABLISHED | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -nr
```

> Systems administrators under a suspected volumetric Denial of Service (DoS) attack extract the foreign IP column of all `ESTABLISHED` TCP connections, sorting and counting them to identify specific remote IPs maintaining hundreds of concurrent connections.

## When should it NOT be used?

- **On modern Linux distributions:** **Reason:** `netstat` relies on the `net-tools` package, which is officially deprecated, unmaintained for decades, and excluded by default on modern RHEL, Ubuntu, and Alpine distributions. **Use instead:** `ss` (Socket Statistics) or `ip`.
- **On high-performance servers with millions of connections:** **Reason:** `netstat` gathers data by opening, reading, and parsing massive plaintext files sequentially in `/proc/net/`. On heavy servers, this blocks execution and introduces significant CPU lag. **Use instead:** `ss` (which queries kernel Netlink sockets instantly).

## Alternatives

- **`ss` (Socket Statistics):** The modern replacement. **Tradeoff:** `ss` is vastly faster, uses binary Netlink APIs, and offers superior filtering syntax (e.g., `ss -t state established`), but forces administrators to unlearn decades of `netstat` muscle memory.
- **`ip route` / `ip -s link`:** The `iproute2` replacements. **Tradeoff:** `netstat -r` and `netstat -i` are effectively replaced by `ip route` and `ip -s link`, consolidating all routing and interface data into a single modern tool suite.
- **`lsof -i`:** File descriptor mapping. **Tradeoff:** `lsof` can identify programs using ports, but is structurally a file inspection tool, not a raw socket and routing visualization tool.

## How it works internally

When you execute `netstat`, it operates entirely in user space by reading and parsing a series of dynamically generated virtual files exposed by the Linux kernel inside the `/proc` filesystem.

For socket connections (like `-t` or `-u`), it sequentially reads the text tables located in `/proc/net/tcp` and `/proc/net/udp`. These files contain hexadecimal representations of IP addresses, ports, and internal socket state integers (e.g., `0A` translates to `TCP_LISTEN`). `netstat` parses these hex values into human-readable IP strings and translates the state integers into strings like `ESTABLISHED` or `TIME_WAIT`.

If the `-p` (program) flag is provided, `netstat` faces a heavy task: the `/proc/net/tcp` file only contains the socket's _inode_ number. `netstat` must rapidly iterate through every running process directory (`/proc/<pid>/fd/`), scanning all open file descriptors to find a symlink pointing to that specific socket inode to correlate the PID with the port. This is why `netstat -p` is notoriously slow on busy servers and requires root privileges.

## Performance Notes

- Always utilize the `-n` (numeric) flag when investigating high-traffic servers. Without it, `netstat` attempts synchronous reverse-DNS lookups for every single foreign IP address connected to the machine, causing the command to hang for several minutes.
- As noted, because `netstat` relies on scraping `/proc/net/` text files, retrieving connection states on a load balancer with 100,000 active connections is extraordinarily inefficient compared to `ss`.

## Security Notes

- **Privilege Masking:** Any user can run `netstat -tulpn`, but the kernel prevents unprivileged users from reading the file descriptors of processes they do not own. Consequently, the `PID/Program name` column will be blank for system daemons (like SSH or Nginx) unless the command is executed with `sudo`.

## Common Mistakes

- **Running without `sudo` for diagnostics:** Wondering why `netstat -p` shows a hyphen (`-`) instead of the program name blocking port 443. **Why it's wrong:** Security boundaries prevent you from seeing root-owned processes. Always run with root privileges when identifying port owners.
- **Relying on scripts parsing `netstat` output:** **Why it's wrong:** The columns in `netstat` are space-delimited and occasionally shift based on IPv6 length or hostname length, breaking brittle `awk` scripts. Modern automation should rely on `ss -j` (JSON output) or specialized metric exporters.

## Best Practices

- Commit the flag sequence `-tulpn` to memory. It is universally recognized as the fastest, most effective incantation for gaining complete situational awareness of listening services on any legacy Linux server.
- Actively transition personal workflows and legacy shell scripts away from `netstat` and toward `ss` (`ss -tulpn`) to ensure your knowledge remains relevant as enterprise distributions continue stripping `net-tools` from base installations.

## Interview Questions

- _Query:_ A junior developer complains that running `netstat -a` on a production web server causes their terminal to hang completely for several minutes. What is the technical cause, and how do you fix the command?
  - _A:_ The `netstat` command attempts to resolve every remote IP address back to a human-readable hostname using reverse-DNS queries. On a production server with thousands of active connections, this triggers thousands of synchronous, blocking network requests. You fix this by appending the `-n` (numeric) flag, which forces `netstat` to bypass DNS resolution and display the raw IP addresses instantly.
- _Query:_ What is the architectural reason `netstat` is being deprecated across all major Linux distributions in favor of the `ss` (Socket Statistics) command?
  - _A:_ `netstat` was built on an antiquated architecture where it must open, read, and parse massive, dynamically generated plaintext files in the `/proc/net/` directory. This is extremely CPU-intensive and slow on heavy servers. `ss` communicates directly with the kernel networking stack using binary Netlink sockets, retrieving socket telemetry virtually instantly without the overhead of text parsing.
- _Query:_ When running `netstat -p`, why are the program names and PIDs populated for some connections but left as blank hyphens (`-`) for others?
  - _A:_ The `-p` flag requires mapping socket inodes to process file descriptors inside `/proc/<pid>/fd/`. The Linux kernel enforces strict access controls; a standard user can only read the `/proc` directories of processes they own. The hyphens represent processes owned by `root` or other users, which are masked for security unless you execute the command with `sudo`.
